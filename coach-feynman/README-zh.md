# coach-feynman 实操指南

## 操作步骤

### step1: 设立学习目标

skill: manage-goal

这个 skill 会帮助设立并管理学习目标。

#### 1.1. 设定原始学习目标

怎么做：
先提出一个原始学习目标。agent 会和你逐步讨论，了解你想学的到底是什么、你最终想达到什么状态，并帮助你把这个目标澄清成一个相对清晰的目标定义。

为什么这么做：
通常，对未知领域的无知会导致一开始提出的目标是模糊的，或者过大、过泛。先和对这个领域有一定了解的人（agent）把目标讨论得相对清楚，后面才有办法判断当前差距、安排学习任务和控制学习范围。

这部分的讨论无需太过具体深入，以我的个人经验来看，从你想学习的目的出发，以达成这个目的为基本目标既可，因为一方面你本就对这个领域不了解，讨论过多，可能导致你发现学习任务过重而放弃；另一方面，过早讨论清楚意义不大，目标可能会随着学习的进展而发生改变。

产出物：
主记录文件中的“目标定义”部分会被明确下来。

#### 1.2. 描述当前水平

怎么做：
agent 会从多个角度和你讨论你当前的基础，关于这部分讨论也不要太过深入太过细节，帮助你基本区分哪些内容你已经掌握，哪些只是模糊了解或根本不懂，从而形成一个对你当前水平的基本描述即可。

为什么这么做：
如果没有对当前水平的判断，就无法估计你和目标之间的距离，也无法判断应该从哪里开始推进。后续的资料收集和学习安排，也会因此失去针对性。同时太过深入的讨论会浪费时间，在后续学习过程中可以慢慢补充细节。

产出物：
主记录文件中的“当前水平”部分会被明确下来。

#### 1.3. 描述学习习惯与单位学习容量

怎么做：
agent 会进一步了解你的学习习惯，包括你可投入的时间、偏好的学习方式、注意力特点等，并和你一起估计你的单位学习容量。

为什么这么做：
这一步的目的，是希望把单次学习任务控制在一个既能推进、又不过载的范围内，避免因为任务长期超出承受能力，而不断积累挫败感，最后越来越觉得自己学不会，越来越不想学。学习中应该要能够获得正向激励反馈，才有可能不断持续。

这里的单位学习容量，指的是你大致能够完成一次 step2 -> step3 -> step4 闭环的容量。这个容量可以用学习时间、学习材料的体量或待解决的问题数量等不同方式不同维度组合描述。尤其要注意在预估时，要预留 step3 和 step4 中整理讲述框架、模拟教学与问答的精力消耗，否则任务会在执行中失控。

这一步也是你了解自己的过程，了解你自己的的真实学习节奏和精力承受能力或者说注意力的利用能力。在了解的基础上，可以进一步通过刻意练习的方法来提升你的单位学习容量。另一方面也要意识到，单位学习容量并非一成不变的，它会根据你的心情，身体状态和学习内容动态变化。因此不用太死板，根据当时的情况灵活调整学习容量。

产出物：
主记录文件中的“学习习惯”与“单位学习容量”部分会被明确下来。

#### 1.4. 拆分阶段性学习任务

怎么做：
agent 会综合前面几步的结果，把清晰的目标定义作为终点，把你当前水平的描述作为起点，再结合你的单位学习容量，将这之间的距离拆分成一个相对合理的阶段性学习任务单，并标出学习里程碑。

为什么这么做：
总目标可能无法一次完成，拆分成若干可以逐步推进的小阶段更为合适。这样后续的资料收集、学习和模拟教学才会有明确边界，也更容易获得反馈，得以调整、回退和迭代。

产出物：
主记录文件中的“阶段性学习任务单”部分会被明确下来，其中包含若干学习里程碑。

### step2: 收集原始学习资料并学习

这一步无需特别的 skill，直接沿用上一步的agent对话继续即可。

怎么做：
围绕当前阶段的学习目标收集学习资料，优先使用你已经拥有的原始资料和一手资料，必要时再要求 agent 协助你补充关键缺口，而不是无限扩展资料范围。

然后阅读并学习这些资料。在学习过程中，尽量用自己的话记录和整理，重点包括：核心概念、关键关系、前置知识、重要例子以及尚未解决的问题（你自己经过思考提出的）。对于其中不懂、不确定或难以理解的部分，可以向 agent 请求协助帮你核对理解、定位依据，并在必要时用**类比**的方式帮助你建立直观认识。

这一步的目标不是立刻整理出完整的教学方案，而是先形成一个初步的理解框架，并逐步暴露并填补理解中的缺口。

为什么这么做：
这一步的重点，不是把当前阶段彻底学透，而是先建立足以支撑下一步起草教学方案的理解基础。

如果过早追求“完全掌握”，很容易陷入资料堆积、过度学习和迟迟不进入输出阶段；但如果理解还过于零散、模糊，后面的教学方案也会变成机械拼接。

通过“收集资料 -> 学习理解 -> 提出问题 -> 请求核对和澄清”这个过程，你可以逐步形成自己的理解结构，并尽早发现前置知识缺口、概念误解和解释上的薄弱点。

当你感觉能够用自己的话大致说明当前阶段的核心内容，就可以进入下一步。
并不一定要强迫自己学习到某种完美程度；如果你已经开始对资料产生明显抵触，往往说明当前阶段的范围、节奏或资料量需要调整。可以使用`manage-goal` 记录并调整自己的学习节奏和计划。这时候休息放松一下吧~

产出物：
一份当前阶段的学习资料清单、学习记录
一份“好了，我要开始装X了”的信心

### step3: 整理教学方案

skill: draft-outline

这一步的重点，不是继续补资料，而是把你在 step2 中形成的理解，先重新组织成一个适合对外讲述的讲述框架，再在此基础上逐步发展成更具体的教学方案。

#### 3.1 搭建讲述框架

怎么做：
基于 step2 中的学习记录和初步理解框架，先整理出一个初步的讲述框架。先不要急着追求完整表达，而是先确定主线和顺序。

优先想清楚：

- 这次讲述最核心的问题或主题是什么
- 应该先讲什么，后讲什么
- 哪些概念必须先解释
- 哪些地方需要补一座“逻辑桥”

为什么这么做：
学习记录是给自己看的，讲述框架是给别人听的，这两者并不一样。你在 step2 中得到的是“我大概理解了”，而这一步要做的是把这种理解重新组织成一个别人能够跟上的讲述框架。

如果讲述框架没有先立起来，后面补再多例子和类比，也只是把内容越堆越散。

产出物：
一份初步的讲述框架。

#### 3.2 完善教学方案

怎么做：
在讲述框架的基础上，进一步补足让别人真正听懂的具体内容，形成一个相对完整的教学方案。这里的重点是补上那些真正服务于讲述的部分，不是把所有学到的内容都塞进去。

你需要着重思考并安排至少这些内容：

- 哪些例子最能帮助理解
- 哪些类比能帮助建立直观认识
- 哪些前提或定义还需要补充
- 哪些地方听众最可能听不懂或跟不上
- 哪些内容虽然你学到了，但在当前讲述中可以先不讲

在起草出基础版本后，可以和 agent 讨论并进一步丰富完善：补足遗漏的前提、调整讲述顺序、增加必要的例子或类比、修正不顺的逻辑连接。

为什么这么做：
只有讲述框架还不够，一个真正能拿来讲的教学方案还需要“血肉”。很多时候你以为自己讲得清楚，其实只是因为脑子里默认了太多前提，存在“知识的诅咒”。

这一步的作用是把“自己懂”和“别人能听懂”之间的差距补上。

产出物：
一份可用于讲解的教学方案初稿（格式不限但推荐markdown文档格式）。

#### 3.3 简化教学方案

怎么做：
在上一步的基础上，再做一次有意识的简化。删掉会分散注意力的部分、重复内容、过早出现的复杂术语，以及对当前讲述目标帮助不大的枝节。

同时检查：

- 主线是否清楚
- 每一部分是否都在为主线服务
- 是否存在明明可以一句话说清，却讲得过长的地方
- 是否存在你自己觉得“讲起来有点拧巴”的地方

为什么这么做：
如果没有这一步，直接进入教学，往往会出现两个问题：

- 自己脑子里觉得懂了，但一讲出来顺序就乱；而整理讲述顺序的过程，本身也是在帮你重新梳理自己的知识结构。
- 内容堆得很多，但听众抓不住主线；而帮听众提炼主线的同时，你也会更清楚这部分内容的主次关系。

先丰富，再简化，是为了避免一开始就讲得太干，也避免后面越补越乱。最终目标不是“内容看起来很多”，而是“别人能听懂，且你自己讲得顺”。

产出物：
一份更适合实际讲解的精简版教学方案（格式不限但推荐markdown文档格式）。

### step4: 教学

根据step1中对相关知识的了解程度的描述，或者你的目标读者/观众（费曼学习法的一些文章说教的时候，要讲到小学生都能听懂，如果你没有你的目标观众，你可以沿用此法）的人设，来生成一个ai。让他在你的教学中可以以他的角度提问。（你也可以上点难度让他深度思考并提问）
在教学过程中，着重收集两方面的问题反馈

1. 来自于你自己感觉到教学中不完美（不丝滑）的部分，想要蒙混过关的地方（诚实面对自己）
2. 来自于你无法准确回答的观众的问题
另外，你可以让你的观众ai帮你精简你的教学方案，去掉一些他已经了解的或者可能不感兴趣的冗余内容
如果存在问题，回到step2
如果没有问题，来到下一步

#### 所需agent

目标读者/观众/学生

### step5(optional but recommand): 真实输出

将你最终教学内容公开发布，收集真实世界的反馈。
