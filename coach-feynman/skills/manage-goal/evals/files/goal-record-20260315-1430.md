# Goal Record

## 1. Overall Goal

**Learning objective:** Understand how the skill-creator skill's evaluation/iteration loop is implemented, including what each component does and why it was designed that way.

**Intended result:** Be able to apply similar patterns when creating your own skills and tools.

**Scope boundaries:**

- Focus on the eval/iteration architecture (run_loop.py, run_eval.py, improve_description.py, generate_report.py)
- Understand how best practices from skill-best-practise.md are applied in SKILL.md
- Learn the "how" and "why" behind design decisions

**Out of scope for this round:**

- Building a complete skill from scratch
- Deep dive into MCP integration or plugin infrastructure
- The coach-feynman skill system itself (meta-learning)

## 2. Current Level Baseline

**What you can already explain:**

- What skills and plugins are at a high level
- Basic skill structure (YAML frontmatter, SKILL.md body)
- You've read skill-best-practise.md

**What you only vaguely recognize:**

- How the evaluation loop actually works in code
- How train/test split prevents overfitting in description optimization

**What you do not understand yet:**

- The stream-event detection mechanism for skill triggering
- How the grader agent evaluates assertions
- How the HTML report generator tracks iterations
- Why specific design choices were made (e.g., 60/40 split, blinded history)
- How agents help in skills: both the agent architecture (grader, analyzer, comparator) AND how subagents are spawned/coordinated in the workflow

**Fragile/misleading areas:**

- May conflate "skill triggering" with "skill execution" - these are tested separately
- May assume the improvement model sees test results (it doesn't - blinded)

## 3. Learning Habits and Unit Capacity

**Available time:** ~3 hours per learning round

**Preferred learning style:** Mix - read files yourself, then discuss patterns and gaps together

**Output format:** Annotated notes explaining how and why the skill-creator works as it does

**Unit learning capacity estimate:**

- **Source volume:** 3-4 core files per round (SKILL.md + 2-3 scripts + 1 agent file)
- **Core concepts:** 4-5 design patterns per round
- **Open questions:** 5-10 questions to resolve through reading + discussion
- **Attention drop-off point:** After ~90 min of dense code reading, need synthesis break

**Overload warning signs:**

- Losing track of which file you're in
- Can't explain a component's purpose in one sentence
- Skimming without retaining

## 4. Staged Task List

### Stage 1: Map the Architecture (Current Stage)

**Goal:** Understand the system at a high level before diving into code details.

**Tasks:**

- [ ] Read SKILL.md structure and identify referenced files
- [ ] Draw a component diagram showing how run_loop.py, run_eval.py, improve_description.py connect
- [ ] Understand what problem each script solves

**Milestone:** Can explain in 2-3 sentences what each core component does.

**Why this size:** Foundation setting - sets up everything else. Light reading, conceptual focus.

---

### Stage 2: Trace the Evaluation Loop

**Goal:** Follow one complete iteration from query to improved description.

**Tasks:**

- [ ] Read run_eval.py: how trigger detection works (stream events)
- [ ] Read run_loop.py: train/test split, iteration management
- [ ] Read improve_description.py: how failures inform new descriptions

**Milestone:** Can trace what happens when you run `python run_loop.py --eval-set ...`

**Why this size:** These three files form one coherent flow. Read together, not separately.

---

### Stage 3: Understand the Grading & Reporting

**Goal:** Learn how results are captured, graded, and visualized.

**Tasks:**

- [ ] Read agents/grader.md: how assertions are evaluated
- [ ] Read generate_report.py: how the HTML viewer works
- [ ] Read references/schemas.md: JSON structures (grading.json, benchmark.json)

**Milestone:** Can explain how a raw query becomes a checkmark in the HTML report.

**Why this size:** Grading + reporting are two sides of the same coin (capture → display).

---

### Stage 4: Extract Reusable Patterns

**Goal:** Translate what you learned into applicable patterns for your own tools.

**Tasks:**

- [ ] Review skill-best-practise.md again - map each principle to what you saw in code
- [ ] Write annotated notes: for each pattern, document how/why skill-creator uses it
- [ ] Identify 2-3 patterns you want to apply to your own skills/tools

**Milestone:** A notes document with "Pattern → How skill-creator uses it → How I'll use it" structure.

**Why this size:** Synthesis work - requires all previous stages complete.

---

### Stage 5: Apply One Pattern (Optional Stretch)

**Goal:** Practice by applying one pattern to a small skill you create or modify.

**Tasks:**

- [ ] Pick one pattern (e.g., parallel baseline comparison, progressive disclosure)
- [ ] Create or modify a small skill using that pattern
- [ ] Test it and note what worked/didn't

**Milestone:** One working skill with intentional pattern application.

**Why this size:** Only if time/energy allows after Stage 4. Not required for core goal.

---

## Stage Rationale

**Why Stage 1 is current stage:** You need the map before the territory. SKILL.md is the entry point - it references everything else.

**Why 5 stages:** The goal breaks naturally along functional boundaries (overview → eval loop → grading → synthesis → practice).

**Why this sizing for 3-hour rounds:**

- Stage 1: ~45 min (light, conceptual)
- Stage 2: ~90 min (dense code, core logic)
- Stage 3: ~75 min (moderate density)
- Stage 4: ~90 min (synthesis, requires re-reading)
- Stage 5: ~60-90 min (hands-on practice)

**First round:** Stages 1-2 fit in one 3-hour session with discussion breaks.

**Next phase starts with:** Stage 1 task execution - read SKILL.md and map components.
